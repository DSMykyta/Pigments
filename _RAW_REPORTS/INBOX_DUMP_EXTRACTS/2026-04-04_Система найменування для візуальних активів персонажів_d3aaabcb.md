## Як реалізовується paper doll у візуальних новелах — поглиблений розбір

### 1. Фундаментальний інваріант

Для LayeredImage критично важливо, щоб висота і ширина в пікселях були однакові для кожного шматка персонажа. Кожен одяг плаває у прозорих пікселях на правильній позиції. Це абсолютне правило. Якщо куртка обрізана по межах куртки — система зламана. Canvas завжди повний, контент плаває всередині.

---

### 2. Як z-індекс у неймінгу відповідає рендер-порядку

Твій `z{zindex}` у назві файлу — це **документація для автора**, а не технічний параметр движка. У Ren'Py LayeredImage порядок рендерингу визначається порядком оголошення атрибутів у коді:

```renpy
layeredimage arthur:
    always: "arthur-body-z10"      # рендериться першим (знизу)
    group base:
        attribute pants ...         # z20
    group top:
        attribute tshirt ...        # z30
    group outer:
        attribute jacket ...        # z40
    group accessory:
        attribute towel ...         # z60
    group face auto:               # z70 — рендериться останнім (зверху)
```

Перший в блоці = нижній шар. Останній = верхній. Код читається знизу вгору — перший атрибут у блоці знаходиться на дні.

---

### 3. Проблема пози та її вирішення

Це головна архітектурна розвилка. Є три підходи:

**Підхід A — Pose-baked (твій поточний)**
Весь одяг містить позу в собі. `jacket_leather-brown_crossed` — куртка вже намальована зі схрещеними руками.

- Плюс: простіша логіка в коді, артист контролює кожну позу окремо
- Мінус: комбінаторний вибух. 3 пози × 5 курток = 15 файлів тільки для курток

Персонаж із 4 нарядами, 4 зачісками і 6 емоціями вже дає 96 комбінацій. Створення статичних зображень для кожної комбінації займає багато місця і часу.

**Підхід B — Розділені рукава**
Тіло одягу (без рукавів) + окремий шар рукавів під або над одягом.

```
arthur-jacket_leather-body-brown_z40.png   ← торс без рук
arthur-sleeve-left-brown_down_z25.png      ← рукав під курткою
arthur-sleeve-right-brown_crossed_z35.png  ← рукав зверху
```

- Плюс: 1 куртка × N поз рукавів замість N курток
- Мінус: артисту складно малювати, потрібна точна стикування

**Підхід C — Умовна видимість (`if_any` / `if_not`)**
Adjust_attributes дозволяє обчислити, додати, відфільтрувати атрибути LayeredImage при виклику команди show — можна виражати складні залежності між атрибутами. Це означає: якщо active поза `crossed` → показуй рукавний шар `crossed`, ховай `down`.

```renpy
group sleeve_left if_any "crossed":
    attribute crossed auto
group sleeve_left if_not "crossed":
    attribute down auto
```

**Рекомендація для твого проекту:** залишайся на Підході A (pose-baked), але додай в неймінг явну `{pose}` як ти вже зробив. Для VN де пози фіксовані (не вільна гра) — це правильний вибір.

### 4. Твій неймінг vs Ren'Py auto-detection

Ключ до ефективного використання layeredimages — правильне іменування файлів. Під час іменування додай префікс для групування: `character_attribute.png` → `character_group_attribute.png`. Це дозволяє використовувати функцію auto.

**Проблема:** твій неймінг використовує дефіси (`-`) як роздільники полів. Уникай пробілів у назвах файлів — якщо назвати `mike shirt.png`, Ren'Py при команді `show mike shirt` показав би тільки сорочку. Використовуй підкреслення замість пробілів. Дефіси мають аналогічну проблему.

**Варіант 1 — Явне оголошення (твій неймінг без змін):**
```renpy
layeredimage arthur:
    group outfit:
        attribute jacket_leather default:
            "arthur-jacket_leather-brown_crossed_z40.png"
        attribute turtleneck:
            "arthur-turtleneck-black_crossed_z30.png"
```

**Варіант 2 — image_format (чистіше):**
```renpy
layeredimage arthur:
    image_format "sprites/arthur/{image}.png"
    group outfit:
        attribute jacket_leather_brown_crossed
        attribute turtleneck_black_crossed
```
Тоді Ren'Py шукає `sprites/arthur/arthur_outfit_jacket_leather_brown_crossed.png` — але ти мусиш перейменувати файли на підкреслення.

**Варіант 3 — config.automatic_images_strip:**
```python
define config.automatic_images = ["-", "_"]
define config.automatic_images_strip = ["sprites/arthur/"]
```
automatic_images сканує файли на диску і коли знаходить файл з `.png`, прибирає розширення, розбиває ім'я по роздільниках і створює image name. Якщо ім'я має мінімум два компоненти — автоматично визначає image.
