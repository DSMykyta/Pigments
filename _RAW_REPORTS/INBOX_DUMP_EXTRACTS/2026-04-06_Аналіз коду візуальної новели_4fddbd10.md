## Критичні баги (гра зламається)

**1. `chemistry` команда в dialogue.js не працює правильно**

В `execute()` для `case "chemistry"` викликається `addChemistry(cn, node.values[cn])`, але в багатьох скриптах (coffee_quest, metro_jacket) використовується формат `{type: "chemistry", who: "Амір", amount: 4}` — з полями `who`/`amount`, а не `values`. Рушій це ігнорує.

```js
// dialogue.js, case "chemistry":
for (var cn in node.values) addChemistry(cn, node.values[cn]);
// Але в скриптах:
{type: "chemistry", who: "Амір", amount: 4}  // ← who/amount ніде не обробляється
```

**Фікс:** додати в `case "chemistry"` обробку `who`/`amount`:
```js
case "chemistry":
  if (node.values) {
    for (var cn in node.values) addChemistry(cn, node.values[cn]);
  } else if (node.who) {
    addChemistry(node.who, node.amount || 0);
  }
  pc = index + 1; execute(pc); break;
```

**2. `say` з `node.chemistry` використовує ім'я як ключ, але `addChemistry` очікує ім'я з CAST**

В intro.js: `chemistry: { "Квінсі": 2 }` — це кирилиця, і `addChemistry("Квінсі", 2)` працює бо `gameState.chemistry.values` теж кирилицею. Ок, це консистентне. Але є ризик якщо десь проскочить short замість name.

**3. `getDialogue()` перевіряє `entry.titles` (рядок 370 dispatcher.js) — але жоден запис в DIALOGUE_ENTRIES не має поля `titles`**

```js
function getActiveDialogue(name) {
  // ...
  if (!entry.titles) continue;  // ← ВСІ записи відфільтровуються!
```

Це означає `getActiveDialogue()` **завжди повертає null**. А `showLocationUI()` використовує це для маркера `*` біля імені NPC. Не критично для гри, але маркер ніколи не з'явиться.

**Фікс:** видалити `if (!entry.titles) continue;` або перейменувати на `entry.label`.

**4. `menu` choices з `next` → `label` → невідповідність**

В intro.js вибори мають `next: "after_choice_1"`, і dialogue.js шукає `currentScript._labels[ch.next]`. Це працює. Але в coffee_quest.js деякі choices мають `label` замість `next`:

```js
// coffee_quest.js:
{text: "Це багато мороки. Потім.", label: "coffee_find_refuse"},
```

А в `dialogue.js` обробляється тільки `ch.next`, не `ch.label`. Ці вибори **не працюватимуть** — клік нічого не зробить, просто перейде на `pc++`.

**Фікс:** в dialogue.js, case "menu", додати fallback:
```js
var target = ch.next || ch.label;
if (target) {
  var t = currentScript._labels[target];
  if (t !== undefined) { pc = t + 1; execute(pc); }
} else {
  pc++; execute(pc);
}
```

**5. `coffee_find_refuse` і `coffee_find_accept` — окремі скрипти, а не labels в тому ж скрипті**

`registerScript("coffee_find_machine", [...])` має menu з `label: "coffee_find_refuse"`, але `coffee_find_refuse` зареєстрований як **окремий скрипт**, не label всередині `coffee_find_machine`. `_labels` шукає **всередині поточного скрипту**. Його там нема.

Це стосується ВСЬОГО coffee_quest.js і metro_jacket.js — десятки зламаних переходів.

**Фікс:** або зробити їх labels всередині одного скрипту, або додати в dialogue.js підтримку `call` при переході на інший скрипт:
```js
// В case "menu", замість _labels lookup:
if (target) {
  // Спочатку шукати label в поточному скрипті
  var t = currentScript._labels[target];
  if (t !== undefined) {
    pc = t + 1; execute(pc);
  } else if (SCRIPTS[target]) {
    // Якщо це окремий скрипт — запустити його
    currentScript = SCRIPTS[target];
    pc = 0;
    execute(pc);
  }
}
```

**6. Немає `loadLocations` визначення в loader.js, але воно є в locations.js**

`loadLocations` визначений в `locations.js`, а `loadCharacters` в `loader.js`. Нормально, бо обидва підключені. Але `loadCSV` використовується в обох, і визначений тільки в `loader.js` який підключається **перед** `locations.js`. Ок, це працює.

**7. `MISSION_DIALOGUE_ENTRIES` і `DIALOGUE_ENTRIES` — coffee_quest.js пушить в них, але вони мають бути визначені ДО coffee_quest.js**

dispatcher.js підключається як `js/systems/world/dispatcher.js`, а coffee_quest.js як `js/scenes/coffee_quest.js`. В HTML dispatcher.js іде **перед** coffee_quest.js. Ок.

Але `BANTER_ENTRIES` використовується в `pair_events.js`, і він теж визначений в dispatcher.js. Ок.

**8. `SPECIAL_MISSION_ENTRIES` перевизначається в coffee_quest.js**

```js
if (typeof SPECIAL_MISSION_ENTRIES === "undefined") {
  var SPECIAL_MISSION_ENTRIES = [];
}
```

Але `var` в JS hoisted на рівень функції/глобальний, тому це **завжди** створить нову змінну якщо missions.js вже визначив `var SPECIAL_MISSION_ENTRIES = []`. Фактично через hoisting — `var` не перезапише, бо обидва глобальні. Але `typeof` перевірка зайва і може створити баг в strict mode. Краще прибрати `if` і покладатися на missions.js.

## Логічні проблеми

**9. Немає механіки "прийняти help request"**

`checkPagerHelpRequest()` надсилає повідомлення і зберігає `gameState._activeHelpRequest`, але **ніде нема UI для прийняття**. Гравець отримує повідомлення на пейджер, але не може на нього відповісти. `executeHelpRequest()` існує але ніколи не викликається.

**Фікс:** додати кнопку в пейджері або автоматичну дію при переміщенні в потрібну локацію.

**10. `getBanter()` ніколи не викликається**

`showLocation()` перевіряє `checkForcedDialogue()`, але **не викликає `getBanter()`**. Парні сцени (pair_events.js) ніколи не запустяться.

**Фікс:** в `showLocation()` після перевірки forced:
```js
// Перевірити banter
if (typeof getBanter === "function") {
  var banter = getBanter(locId);
  if (banter && banter.label && SCRIPTS[banter.label]) {
    hideHUD();
    runScript(banter.label);
    return;
  }
}
```

**11. `getMissionDialogue()` ніколи не викликається**

Місійні міні-діалоги (coffee_find_machine тощо) зареєстровані в `MISSION_DIALOGUE_ENTRIES`, але `_executeMission()` не викликає `getMissionDialogue()`. Місія просто дає результат без діалогу.

**Фікс:** в `_executeMission()`, перед показом результату:
```js
if (partner) {
  var missionLabel = getMissionDialogue(partner);
  if (missionLabel && SCRIPTS[missionLabel]) {
    // Запустити місійний діалог, а результат показати після
    runScript(missionLabel);
    return;
  }
}
```

**12. День 31 перевірка — `_goToSleep` перевіряє `day >= 31`, але `nextDay()` інкрементує день**

Якщо день = 30 і гравець спить, `nextDay()` робить день 31. Потім наступного разу коли спить з дня 31 — перевірка `>= 31` спрацьовує і запускає фінал. Це правильно. Але якщо гравець не спить на 31 день — фіналу не буде. Потрібен примусовий фінал.

**13. Немає обмеження на кількість розмов за день з одним NPC**

Гравець може клікати на NPC нескінченно, кожен раз отримуючи +1 хімію і витрачаючи 15 хв. Cap в 15 хімії/день не допомагає бо є 6 NPC × 15 = 90 хімії/день, що ламає баланс.

**Фікс:** обмежити розмови (2-3 на NPC на день) або прибрати +1 за повторний stub.

**14. `advance()` — клік на game-screen прокручує діалог, але також може випадково тригернути після закриття оверлею**

`advance()` прив'язаний до всього `game-screen`. Коли оверлей закривається, наступний клік може просунути діалог.

## Чого не вистачає

**15. Немає системи "піти спати" крім бекруму**

Гравець МУСИТЬ повернутися в бекрум щоб спати. Але якщо гравець не знає цього — він застрягне.

**16. Немає попереджень про час**

Якщо `minutes > 1440` (після півночі) — `isNight()` true, NPC зникають, але гравець все ще ходить. Немає підказки "пора спати".

**17. Немає системи подарунків в UI**

`giveGift()` існує, але **немає UI для дарування**. Ні кнопки, ні меню.

**Фікс:** додати бонусну опцію "Подарувати" при розмові з NPC (якщо є предмети).

**18. Немає підтвердження видалення збереження**

`_deleteSelectedSlot()` видаляє без підтвердження.

**19. `_escapeHtml` не визначена в loadscreen.js**

`_escapeHtml` визначена в `overlays.js`, але `loadscreen.js` її використовує. Оскільки обидва глобальні і overlays.js підключений раніше — ок. Але це крихкий зв'язок.

**20. Пейджер ховається коли немає повідомлень**

`updatePagerScreen()` ховає пейджер коли черга порожня. Але пейджер також показує час/день — це корисна інформація навіть без повідомлень. Зараз він просто зникає.

## Архітектурні проблеми

**21. Два формати для menu choices: `next` vs `label`**

Intro використовує `next`, coffee_quest використовує `label`. Рушій підтримує тільки `next`. Потрібна єдина конвенція.

**22. Скрипти як окремі registerScript vs labels всередині одного скрипту**

Intro — один великий скрипт з labels. Coffee quest — багато маленьких скриптів з menu-переходами між ними. Рушій не підтримує крос-скриптові переходи з menu. Це **головна архітектурна проблема**.

**23. Hades-стиль диспетчер потребує більше записів**

Зараз `DIALOGUE_ENTRIES` має тільки ~5 записів (день 30, coffee group, coffee cafe find). Для Hades-стилю потрібно 50-100+ записів по 2-5 на NPC на рівень хімії. Без цього гравець бачить тільки stubs.
