### assistant · 2026-04-17T13:54:24.368687Z

Для S і V — звичайне арифметичне середнє: (S1+S2)/2, (V1+V2)/2.

Для H складніше, бо це кут на колі (0-360°). Дві формули:

**Проста (працює якщо різниця hue < 180°):**
```
H = (H1 + H2) / 2
```
Для твого випадку: різниця 176°, формула працює → 109°.

**Векторна (правильна завжди):**
```
x = cos(H1) + cos(H2)
y = sin(H1) + sin(H2)
H = atan2(y, x)
```
Переводиш hue у точку на одиничному колі, усереднюєш координати, повертаєш назад у кут. Це бере коротший шлях.

Різниця видна коли hue близько до 0°/360°. Наприклад H1=350°, H2=10°:
- Проста: (350+10)/2 = 180° (протилежний бік кола, неправильно)
- Векторна: 0° (правильно, бо 350° і 10° майже однакові)

У твоєму випадку 21° і 197° — різниця рівно на межі. Векторна формула дала б той самий 109°, але з нюансом: коли різниця точно 180°, результат невизначений (дві точки протилежні, "середина" — будь-яка з двох перпендикулярних). Помаранчевий+блакитний близькі до цього, тому результат HSV-усереднення особливо нестабільний — крихітний зсув в одну сторону дає зелений, в іншу — фіолетовий.

Саме тому HSV-змішування в графіці майже не використовують. Для нормального змішування беруть LAB або OKLCH.

### assistant · 2026-04-17T13:56:10.542036Z

Обидва перцептивні (однакові математичні кроки = однакові візуальні кроки), але різні.

**LAB (CIELAB, 1976)**
- Історичний стандарт, є скрізь — Photoshop, print, наука.
- Працює, але має баги: сині кольори при змішуванні йдуть через фіолетовий, жовті через зелений. Градієнт від синього до білого виглядає не зовсім природно.
- L (світлість) не ідеально рівномірна — темні відтінки сприймаються трохи інакше ніж світлі при однакових кроках.

**OKLCH (2020, Björn Ottosson)**
- Переробка LAB з виправленими помилками. Синій змішується через синій, не через фіолетовий.
- L справді рівномірна — градієнти виглядають ідеально плавними.
- Нативна підтримка в CSS з 2023, всі сучасні браузери.
- Формат зручніший: L (0-1), C (chroma/насиченість), H (hue в градусах) — як HSV але працює правильно.

**Що використовувати:**
- Для вебу, дизайну, градієнтів, UI — **OKLCH**, без варіантів. Кращий результат, простіший синтаксис.
- Для друку, роботи з ICC профілями, наукових задач — **LAB**, бо вся інфраструктура на ньому.
- Для кольорових палітр і design tokens — OKLCH, бо можна тримати однакову L і C, міняти тільки H — і всі кольори палітри матимуть однакову візуальну вагу.

Для твого прикладу (#c86733 + #29c2ff навпіл) OKLCH дасть приблизно сірий з легким холодним відтінком — те що мозок очікує від змішування комплементарних. LAB дасть схоже, але з ледь помітним фіолетовим зсувом.

H циркулярно дає 330° замість очікуваного "центру" → **LAB(64, 44, -25)**, рожево-пурпуровий. Та сама пастка що HSV, але в перцептивному просторі — все одно ламається на комплементарних бо усереднює кут між ними не звертаючи уваги на те що chroma мала б скасуватись.

**Oklab (декартовий)**
L(0.705), a(-0.005), b(-0.005) → приблизно **#AFAFB1**, майже ідеальний нейтральний сірий з мікроскопічним холодним відтінком. Найчистіший "справжній" сірий з усіх систем.

**OKLCH (Oklab в циліндрі)**
Та сама проблема що LCH. H усереднюється по колу, chroma залишається високою → фіолетовий або рожевий, не сірий.

**XYZ**
Лінійний простір, працює як Linear RGB — дає синюватий результат, приблизно **#909FBE**. Це математична основа під LAB.

---

**Що тобі треба для сіро-синього з комплементарних:**

sRGB (#799599) або Linear RGB (#909FBE) — єдині системи які природно дають синюватий результат на цій парі. Перцептивні (LAB, Oklab) дадуть чистий сірий без ухилу в жоден бік. Циліндричні (HSV, HSL, LCH, OKLCH) зламаються. CMYK дасть мул.

Якщо хочеш ще більший ухил у синій — візьми середнє з **вагою** на синій колір. Наприклад 40% помаранчевого + 60% синього в sRGB дасть темніше і синіше. Або залиш RGB середнє і потім в Oklab трохи додай синього chroma вручну — це дає контроль без артефактів.
